## What files do we download? 

Determined by the GL_PRODUCTS argument in 05_download.R
02_crawl.R just finds all available files

- lidar/geotiff
   - chm: canopy height model
   - dtm: digital terrain model (bare earth)
   - dsm: digital surface model (top-of-surface)
   - slope: slope
   - (NOT INCLUDED): CHM_mean
   - (NOT INCLUDED): CHM_rugosity
   - (NOT INCLUDED): DSM_mean
   - (NOT INCLUDED): DSM_rugosity
   - (NOT INCLUDED): aspect
- lidar/geotiff/metrics (note that these are for all points, not just trees) 
   - p[0-9]: height percentiles	(10% increments) of all returns 
   - d[0-9]: density deciles (10% increments) of all returns 
   - mean: mean of all return heights
   - qmean: quadratic mean of all return heights
   - kurt: kurtosis of all return heights
- lidar/shp
   - *tiles.shp: coverage tiles
- lidar/las
   - *.las: point cloud files
- (NOT INCLUDED) trajectory/shp
   - *gnd-trajectory.shp: flight trajectory
- metadata
   - *metadata.pdf: flight metadata
- (NOT INCLUDED) photography/orthomosaic
   - *ortho.tif: high-resolution imagery tiles

  ## .las tiling scheme
  Explains how tiles are organized in the shapefile
  - "cXrY": rectangular grid over bounding box, with most of it being empty. one polygon per 1km x 1km tile.
  - "lXsY": one polygon per flightline --> 1:1 with what data exists 

  Both options overestimate (cXrY include empty 1km grids, lXsY envelopes a swath rather than tracing it) 

  ## Handling mosaics
  A few campaigns (*EV[0-9]_all) are mosaics of a bunch of other flights over the same epoch. These need to be handled
  differently or filtered out, so the is_mosaic column is a flag for this.
